## 1. Permission Model Overview

OpenCode agents inherit permissions based on their `mode`:
- **primary**: Can invoke subagents, read/write files, run shell commands
- **subagent**: Can read/write files, run shell commands, but **cannot invoke other subagents** (depth limit)

## 3. Safety Constraints (All Agents)

1. No production DB changes without approval
2. No deployment without approval
3. No user/password changes
4. No secrets in code or logs
5. No mock/stub code for real functionality
6. No claiming PASS without evidence
7. No force push or destructive git operations
8. No hardcoded secrets
9. No auto-migration on production
10. No creating projects from scratch

## 5. Depth Limit

- **Max depth**: 3 levels (Orchestrator → Specialist → Sub-specialist)
- Specialists cannot invoke the Orchestrator
- Specialists can invoke other specialists only if explicitly needed and within depth limits
- OpenCode enforces this via the `subagent` tool availability (subagents don't have access to `subagent` tool)
