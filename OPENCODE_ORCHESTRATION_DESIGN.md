## 1. Orchestration Flow

```
User Request → Orchestrator → Analyze → Decompose → Delegate → Collect → Review → Report
```

### 1.1 Steps

1. **Analyze**: Orchestrator reads user request, identifies goal, scope, constraints
2. **Decompose**: Break into specialist tasks with dependencies
3. **Delegate**: Invoke subagents via `subagent` tool with task details + context
4. **Collect**: Wait for all subagents to complete
5. **Detect conflicts**: Compare results, identify disagreements
6. **Review**: Invoke Code Review Agent for independent verification
7. **QA**: Invoke QA Agent for testing (if code changes exist)
8. **Fix**: Delegate fixes to appropriate specialist
9. **Re-test**: Verify fixes work
10. **Report**: Unified report with PASS/FAIL/NOT VERIFIED/BLOCKED

### 1.2 Delegation Rules

| Rule | Description |
|------|-------------|
| Minimum delegation | Only invoke agents needed for the task |
| Parallel when safe | Independent analysis tasks can run in parallel |
| Sequential for dependencies | If Agent B depends on Agent A, wait for A first |
| Always review | After code changes, invoke code-review agent |
| Always test | After code changes, invoke QA agent |
| Accounting review | Any financial change must be reviewed by accounting agent |
| Delegation limits | Max depth 3, max retries 3, max parallel 5 |
| No circular delegation | Specialists cannot invoke orchestrator |

### 1.3 Conflict Detection

After collecting results from multiple agents:
1. Compare findings — do they agree?
2. If conflicts: present both views, identify the disagreement
3. If one agent contradicts another: investigate which is correct
4. If agents disagree on approach: present options to user

### 1.4 Error Handling

- If a subagent fails: log the error, retry up to 3 times
- If a subagent is unavailable: try alternative agent or report BLOCKED
- If a subagent returns incomplete results: request clarification
- If agents conflict: present both views, request resolution
- If max retries exceeded: mark as BLOCKED, report to user

### 1.5 Reporting Format

```
## Task: [description]
### Agents Invoked
- [agent1]: [summary]
### Changes Made
- [file1]: [what changed]
### Tests Run
- [test1]: PASS/FAIL
### Conflicts Detected
- [conflict] → [resolution]
### Remaining Issues
- [issue]: [status]
### Status: PASS / FAIL / NOT VERIFIED / BLOCKED
```

## 4. Safety Rules (All Agents)

1. No creating projects from scratch
2. No deleting functions/data without verification
3. No production DB changes without approval
4. No deployment without approval
5. No user/password changes
6. No mock/stub code for real functionality
7. No claiming PASS without evidence
8. No force push or destructive git operations
9. No hardcoded secrets
10. No auto-migration on production
